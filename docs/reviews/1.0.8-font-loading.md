# 1.0.8 runtime font investigation

The user applied 1.0.8 successfully and starts the game directly from Steam,
but the supplied screenshot still resembles the previous font. The cause on
that machine has not been established. Do not describe another font release
as a fix until the runtime paths have been checked.

## Verified release contents

The published Windows NSIS installer was downloaded, its `app-64.7z` extracted,
and the embedded translation payload decompressed. Its version is 1.0.8. The
four font asset SHA-256 hashes match `tools/diagnose_font.ps1` and differ from
1.0.7. This verifies the published installer contents, not the user's active
game assets.

## Loader behavior

Source: OpenKH tag `release2-1691`, commit
`7a3b945c538d32c6a285128c98aefba093f52ceb`:

- `OpenKh.Research.Panacea/Panacea.cpp`, `sortRemasteredFiles`: DDS files sort
  before PNG files. `ScanRemasteredFolder` can replace the remastered entry
  list with that sorted directory listing. Additional DDS files can therefore
  select older font images even when the installed PNG files are current.
- `GetRemasteredFiles` checks `dev_path` before `mod_path`.
- `OpenKh.Research.Panacea/OpenKH.cpp`, `ReadSettings`: exact keys, UTF-8 paths,
  last duplicate key wins; no whitespace trimming.
- The manager uses `state.modRoot` when an installation state exists. That
  path can differ from the active loader configuration. The manager's success
  message does not establish which font the running game reads.

These are possible explanations, not confirmed findings on the user's machine.

## Read-only diagnostic

Download `tools/Check-KH2FM-Font.cmd` on Windows, run it and choose the folder
containing `KINGDOM HEARTS II FINAL MIX.exe`. It is self-contained. It writes
only `KH2FM-font-report.json` next to itself, and also prints the report. It
does not change loader settings, mod files, registry entries or saves.

`tools/diagnose_font.ps1` is the same diagnostic for explicit invocation:

```powershell
./tools/diagnose_font.ps1 -GameDir 'C:\Games\KH' -ReportPath './font-report.json'
```

Report fields include the installation-state version and path, active mod,
development and extracted paths, four font hashes, remastered directory file
names/hashes, loader hashes and running game executable paths. It does not
claim that matching files prove in-game rendering or Steam's selected copy.

The PowerShell body was exercised under verified official PowerShell 7.5.3 on
Linux against real published 1.0.8 font bytes, additional uppercase DDS files,
duplicate mod paths, a mismatched installer-state path, a development font
override, and missing settings/state. Every case passed; game file hashes were
unchanged. Windows folder selection and the CMD wrapper still require a native
Windows run. The source uses Windows PowerShell 5.1-compatible syntax.

The CMD body is generated by appending the PS1 after a `# POWERSHELL` marker;
keep both bodies identical when editing the diagnostic.
